# QQ / 微信 AI 好友：开源项目与接入方式核查

核查日期：2026-10-20。依据项目维护者的仓库、代码、发行页、官方文档和腾讯自己的插件仓库。这里只完成资料与部分源码核查，没有安装这些项目、登录微信、验证用户账号资格或证明端到端可用。README 的能力声明和用户 Issue 的复现报告分别标明，均不等于本机实测。

用户后续确认“QQ 也行”。因此整体第一轮建议改为 **AstrBot + QQ 官方机器人先验证；如果必须普通 QQ 好友形态或插件依赖 OneBot，评估 AstrBot + NapCat**。微信 iLink 保留为跨平台第二候选。下方微信部分保留作为原需求的完整调研依据。

## QQ 路线追加核查

| 路线 | 实际账号和添加形态 | 通道能力与待验收项 | 授权与选型判断 |
| --- | --- | --- | --- |
| AstrBot + QQ 官方机器人 | 创建的是 QQ 开放平台机器人，不是接管普通 QQ 账号；可以扫码进入单聊、从联系人中的“机器人”页管理 | AstrBot 当前 WebSocket 教程列文字、图片、语音、视频、文件收发与主动推送；可扫码创建，自动填 AppID / AppSecret | **优先做最小验证**。插件若写死 aiocqhttp / QQ 号或调用非官方扩展 API，仍需改适配，不能承诺所有陪伴插件即插即用 |
| AstrBot + NapCatQQ | 在已登录 NTQQ 的普通 QQ 账号上实现协议端，再通过 OneBot v11 反向 WebSocket 对接 AstrBot；对外形态更接近普通 QQ 好友 | 私聊、群聊等能力走 OneBot；不需要微信 UI 自动化。实际兼容取决于 QQ 构建、NapCat 版本、账号和所用 API | 普通好友形态或 OneBot 插件优先时的备选；不是腾讯官方 Bot API。当前 NapCat 采用限制性混合许可，不能简单称 MIT / GPL 自由商用 |

官方 QQ 的扫码与群聊方式依据 [AstrBot WebSocket 接入文档](https://docs.astrbot.app/platform/qqofficial/websockets.html)；普通账号协议桥接依据 [NapCat 主仓库](https://github.com/NapNeko/NapCatQQ)与 [AstrBot OneBot 接入文档](https://docs.astrbot.app/platform/aiocqhttp.html)。上表优先级是针对本需求的判断，均未在用户账号上实测。

### QQ 官方主动消息规则与常见旧教程的差别

2026-10-20 读到的腾讯[消息收发概述](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/overview.html)列出：

- 普通 QQ 单聊的被动回复窗口为 60 分钟，每条用户消息可回复 4 次；QQ群为 5 分钟、5 次。
- 普通单聊的主动消息每日上限为每用户 1000 条；群聊为每群 1000 条，另有频控，用户可以关闭“允许主动发送”。这不是建议发送量，也不代表每个账号所有权限都已获得。
- 单聊主动消息单关系频控 20 条/分钟；Bot 总限速按认证状态区分。群聊同样单关系 20 条/分钟，Bot 总量按认证区分。
- 另有 30 天内四个阶段各一条的“互动召回消息”。“频道私信”每天每用户 2 条主动消息是另一个场景，不能套到普通消息列表单聊。

不要继续引用旧教程的“QQ 只能 @ 回复、主动推送一天只能 5 条”作为当前统一结论。实际账号开关、权限、服务返回码和框架发送方式仍要验收；接口文档中的额度不是账号现状的证明。[腾讯单聊发送接口](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_users_user_openid_messages.post.html)、[群聊发送接口](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_messages.post.html)

AstrBot 当前教程还说明：扫码创建后从开放平台“扫码聊天”进入；机器人加群目前要求自己是群主，且可在群设置打开全量消息和主动发言。这比“任意加群、随意读取全部群消息”有明确边界。[群聊设置步骤](https://docs.astrbot.app/platform/qqofficial/websockets.html)

### NapCat 当前维护和许可边界

[发行页](https://github.com/NapNeko/NapCatQQ/releases)最新可见 v4.18.38 / 2026-10-12，近期持续更新。维护者对 v4.18.37 的证据特意区分了“无登录启动成功”和“登录后运行”，并列出 Windows QQ 9.9.33-52230 的无登录启动检查；不能把兼容表覆盖范围都宣称为完整实测。本次也没有登录验证。

[NapCat LICENSE](https://github.com/NapNeko/NapCatQQ/blob/main/LICENSE)标题为 Limited Redistribution License，包含非商业用途、未经明确许可不得使用/修改等限制；README 还写混合许可、禁止未经作者授权基于 NapCat 代码开发。因此它是公开源码的参考与现成协议端候选，**不适合当作可以任意复制、改造并商业发布的宽松开源底座**。需要区分“写自己的 AstrBot 插件，通过 OneBot 接口连接已有程序”与“直接复制修改 NapCat 源码”；授权有疑问时不要自行扩张解释。

建议先以 QQ 官方机器人验证文字、人设、分段、原生语音条和少量主动问候。若现成陪伴插件只支持 OneBot，再评估移植到官方适配器的成本，与使用 NapCat 普通账号方案比较。QQ 空间动态、Android 设备看屏和控制仍是另外的模块，不能从 OneBot 或官方 Bot 的基础聊天能力推导出来。

## 先区分三种“在微信里聊天”

| 形态 | 用户实际看到的入口 | 是否等于普通微信好友 | 对本需求的适合程度 |
| --- | --- | --- | --- |
| 微信 ClawBot / iLink | 个人微信聊天列表中的 AI 助手会话，用户扫码授权自己的后端 | 不是把某个普通微信小号变成机器人；不能据此承诺加好友、拉群、朋友圈或任意联系人收发 | 若接受专属助手入口，优先核验 |
| Windows 微信桌面自动化 | 一个正常登录的个人微信账号，由本地程序操作窗口收发 | 对其他人可以呈现为普通好友，但依赖桌面登录和界面适配 | 追求普通账号形态时的备选 |
| 公众号、企微自建应用、微信客服 | 公众号会话、企业内部应用或客服入口 | 不是普通好友；三种入口也不能互相替代 | 面向客服、知识问答或组织场景时再选 |

ClawBot 形态、扫码流程见 [CowAgent 微信文档](https://docs.cowagent.ai/channels/weixin)、[LangBot 当前接入文档](https://docs.langbot.app/en/usage/platforms/wechat/weixin.md)。企业内部应用与对外微信客服的明确区别见 [CowAgent 微信客服通道说明](https://github.com/zhayujie/CowAgent/blob/master/channel/wechat_kf/README.md)。桌面自动化边界见 [wxauto 技术说明](https://docs.wxauto.org/)。上表“适合程度”是本次选型判断。

## iLink 官方路线：能确定什么，仍不能保证什么

腾讯目前公开 [Tencent/openclaw-weixin](https://github.com/Tencent/openclaw-weixin)，提供扫码授权、凭证保存、消息轮询和媒体处理。其 [LICENSE](https://github.com/Tencent/openclaw-weixin/blob/main/LICENSE)明确 MIT；[后端协议文档](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol.md)默认服务地址为 `ilinkai.weixin.qq.com`。这是比非官方网关更优先的入口候选，但开源插件不意味着腾讯服务端开源，也不是不限时、不限量的消息推送服务。

- **账号前提**：AstrBot 当前文档写明手机微信 iOS >= 8.0.70、Android >= 8.0.69，而且微信中需要有 ClawBot 插件。版本达到要求不等于用户账号必然可授权；本次没有操作用户手机确认资格。[AstrBot 接入文档](https://docs.astrbot.app/platform/weixin_oc.html)
- **形态前提**：扫码者使用自己的微信进入 ClawBot 助手会话。不能把此流程描述成“机器人注册了普通微信号，任何人加它好友都能聊天”；后者是另一种部署形态。[LangBot 扫码和使用流程](https://docs.langbot.app/en/usage/platforms/wechat/weixin.md)
- **框架前提**：腾讯原插件给 OpenClaw 使用，当前文档要求 Node.js >= 22.13.0，建议 OpenClaw >= 2026.5.12；AstrBot / CowAgent 是各自实现接入，不必为了使用它们额外完整安装 OpenClaw。[腾讯官方 README](https://github.com/Tencent/openclaw-weixin/blob/main/README.zh_CN.md)、[AstrBot 适配器源码](https://github.com/AstrBotDevs/AstrBot/blob/master/astrbot/core/platform/sources/weixin_oc/weixin_oc_adapter.py)
- **主动消息前提**：CowAgent 文档按用户最后消息后 24 小时说明主动发送窗口。腾讯仓库 [Issue #202](https://github.com/Tencent/openclaw-weixin/issues/202)同时记录 24 小时和主动消息条数限制诉求，维护方回复正在催促产品重新评估；[Issue #309](https://github.com/Tencent/openclaw-weixin/issues/309)又有约 15 小时无入站后被拒收的复现。因此应按“有会话有效期和额度约束，需要真实账号验证”设计，不能承诺固定 24 小时 SLA，更不能承诺用户几天不说话仍无限主动关心。
- **语音前提**：AstrBot `weixin_oc` 文档只支持收语音、不支持发语音条；接收端使用微信云端转录。CowAgent 当前源码明确把 TTS 当文件发送。**生成了声音 ≠ 已实现视频中那种微信原生语音条、实时语音或通话。**[AstrBot 能力表](https://docs.astrbot.app/platform/weixin_oc.html)、[CowAgent 当前源码](https://github.com/zhayujie/CowAgent/blob/master/channel/weixin/weixin_channel.py)
- **功能边界**：腾讯协议文档特别提醒，字段存在不代表服务端完整契约或客户端已实现该能力。因此不能看到 `group_id` 字段就承诺能拉群，也不能把 ClawBot 当朋友圈或手机屏幕控制 API。[腾讯协议说明](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol.md)

## wxauto 的“开源”和“免费”需要拆开

1. [旧 `cluic/wxauto` 的 pyproject](https://github.com/cluic/wxauto/blob/main/pyproject.toml)写 `39.2.1` / `wxauto 3.9 archive version`；[源码](https://github.com/cluic/wxauto/blob/main/wxauto/wxauto.py)还保留 `VERSION = '3.9.11.17'`。这份可读源码适合学习 UI 自动化，不能推断支持用户当前 4.x 客户端。
2. [原作者 `cluic/wxauto4`](https://github.com/cluic/wxauto4)当前仅留“停止更新”，没有完整当前源码。
3. [官方现行安装页](https://docs.wxauto.org/docs/install.html)推荐免费 `wxauto4`，标注支持客户端至 4.1.8.107；增强版 `wxautox4` 需购买激活码。[PyPI 原作者发行](https://pypi.org/project/wxauto4/)当前可见 41.1.7 / 2026-09-01，以 Windows wheel 形式发布。可免费下载使用不等于我们已获取完整可维护源码。
4. 免费版 Python 支持范围在文档与 PyPI 分类之间有差异，实际部署应以目标解释器是否有对应 wheel 和最小测试为准。Plus 激活、更新期限和授权范围见[官方常见问题](https://docs.wxauto.org/docs/issues.html)；不能把旧仓库 Apache-2.0 套到所有新二进制发行和商业用途上。
5. UI 自动化仍依赖已登录桌面、界面布局和账号状态。官方明确不保证不会有功能或账号限制，不能称为“免封号”。这是一条需要持续维护的通道，不是单靠接 DeepSeek 就完成的产品。[wxauto 风险与支持范围](https://docs.wxauto.org/docs/issues.html)

## 微信单平台情况下的建议落地顺序

**第一候选：AstrBot + 官方 iLink + DeepSeek + 经核验的陪伴插件。** 优点是已有消息管理、人格配置和插件接点，可以把工作集中在自然分段、记忆、主动问候等陪伴体验。先验证用户 ClawBot 资格、文字对话、重启恢复与会话失效处理。插件如果只声明 QQ / OneBot 支持，需要移植或适配，不能直接保证微信全部功能可用。这是选型建议，不是已完成部署。

**普通好友形态备选：Windows 微信自动化适配器 + 独立聊天核心。** 适用于用户坚持使用可加好友的普通微信账号；先核对微信实际版本、免费包能否监听指定会话、授权和源码可维护性，再决定采用现行 wxauto 发行还是其他当前开源实现。不要先锁死在旧 3.9 版本或已归档 Hook 项目上。

**通用私人助手候选：CowAgent。** 如果后续重点变成查资料、定时提醒、记忆与工具调用，比单纯拟人陪伴更合适。**可视化工作流候选：LangBot + Dify。** 如果主要需求是编排知识库、客服或业务流程，这条路线比给普通聊天硬加复杂后台更合适。

无论哪条路线，DeepSeek 是模型层，微信接入是消息层，人设与记忆是产品层；“一起刷视频、看手机屏幕、发朋友圈”还需要独立的设备或平台工具，并要通过实际可见结果验收，不能让模型口头声称执行就算完成。
