# 定时提醒

使用 AstrBot 4.29.1 原有 future_task、未来任务面板和持久化调度，不另建提醒服务。

## 在 QQ 聊天中使用

对希望发送提醒的机器人说清楚时间和内容，例如：

- “十分钟后提醒我去取快递。”
- “明天早上八点提醒我带雨伞。”
- “每个工作日晚上九点提醒我复习英语。”
- “列出我在这个聊天里的提醒。”
- “取消每天晚上九点复习英语的提醒。”

两个人格均已配置原有提醒工具。任务属于创建它的聊天和用户；在大肥鱼创建的提醒不会自动转给 GPT大人，也不能从另一个机器人聊天里取消。新建自定义人格时，如需提醒，应在原有工具选择中保留 future_task 和 send_message_to_user。

时间按 Asia/Shanghai 理解。时间或重复规则不清楚时需要先明确；以机器人调用工具后的确认时间及任务面板保存的时间为准。框架给模型的当前时间精确到分钟，因此“几分钟后”也按分钟理解，不作为秒级计时器。

## 查看、修改与取消

管理面板左侧“未来任务”可以查看保存的提醒、下次执行时间、启用状态和目标会话，并编辑、停用或删除。一次性提醒使用执行时间，重复提醒使用原有 Cron 规则；通常直接在 QQ 里描述即可，无需自己写规则。

通过管理面板直接创建的任务不带聊天创建者，聊天工具出于归属检查可能拒绝修改或取消它；这类任务回到管理面板处理。管理面板属于本机管理员，能管理全部任务；聊天工具只列出并管理当前聊天、当前用户创建的任务。

取消成功表示任务已从原有数据库和调度器移除；只在聊天里说“取消”，而模型没有成功调用工具，不算取消成功。不要用删除聊天记录代替取消提醒。

## 运行条件与边界

- 电脑需要开机、联网，本地 AI 好友服务需要运行；关闭面板网页不会停止后台服务。
- 任务存储在本机，服务重启后会恢复；电脑关闭期间无法发送，离线或网络失败时不保证补发。
- 到点后，原有任务系统会唤醒模型并调用消息工具投递，实际收到时间还受网络、模型响应和 QQ 接口影响。
- 当前上游一次性任务在执行结束后会移除，即使该次执行失败也可能被移除；任务从面板消失不能单独证明手机已经收到。
- 主动陪伴权限仍按原有配置控制；用户明确创建的定时任务使用原有任务链路，不会因此开启对所有联系人的主动聊天。

## 检查入口

scripts/check_reminder_setup.py 只检查现有人格的工具权限、时区和任务数量，不改人设、不创建或发送任务，也不输出提醒内容、目标用户或密钥。结果保存在 verification/reminder-readiness.json。

实际手机投递和重启验证以《MVP交付验收.md》及本轮提醒验收记录为准，不能只看接口返回或任务列表。
