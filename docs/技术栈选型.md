# AI 好友技术栈选型

日期：2026-10-20。用户要求复用已有开源代码。现已完成本机安装、面板登录、插件加载和本地测试；DeepSeek 密钥与 QQ 账号联调按用户要求暂缓。具体验收边界见《MVP交付验收.md》。

## 选型结论

采用 **Python 3.12 + AstrBot + QQ 官方机器人 WebSocket + DeepSeek 官方 API + 现有陪伴插件 + 本地存储**。语音输出采用 AstrBot 已有 Edge TTS 接口。以部署、配置和验证已有组件为主，确认实际缺口后才写小型 AstrBot 插件。

## 组件与职责

| 层次 | 决定 | 复用边界与依据 |
| --- | --- | --- |
| 语言与环境 | Python 3.12.15，Conda 独立环境 | 按用户要求使用 Conda，安装位置为 E:\\chatbot\\runtime\\conda；依赖遵循选定发行版 |
| 主程序 | AstrBot 4.29.1 作为首轮验证基线 | 复用消息事件、会话、模型提供商、插件加载、媒体处理与管理界面；固定发行版，验证后再认定为可运行组合 |
| QQ 接入 | AstrBot 内置 QQ 官方机器人 WebSocket 适配器 | 使用现有扫码创建和私聊能力；该入口有机器人身份，不接管普通 QQ 号 |
| 对话模型 | DeepSeek 官方 API，默认 deepseek-flash | 复用 AstrBot 现有模型接入；密钥由本地管理界面配置 |
| 人设与上下文 | AstrBot 现有人格、会话与上下文配置 | 保持一个主回复入口，避免多个插件各自回复造成重复 |
| 陪伴与主动联系 | astrbot_plugin_private_companion V1 6.7.0 | 复用状态、日程、主动联系及现有定时机制；不开第二套调度服务；V2 不纳入首轮基线 |
| 长期记忆 | 首选验证 astrbot_plugin_memory_companion 2.3.1 | 当前 metadata 仅声明 aiocqhttp，不把 QQ 官方通道兼容性当已确认；若无法直接使用，先换支持官方通道的现有记忆插件，不启动自研记忆引擎 |
| 存储 | 框架自带本地存储；插件沿用已有 JSON / SQLite 后端 | 各组件按自己的数据契约保存，不强行合并数据库，不另写 ORM 或向量检索服务 |
| 语音输出 | AstrBot 内置 Edge TTS 提供商 + edge-tts + FFmpeg | 用普通中文音色验证生成与 QQ 原生语音发送；Edge TTS 需要外部服务，服务可用性待测 |
| 管理界面 | AstrBot 自带 WebUI 和插件现有面板 | 直接使用发行包中的界面；不新增独立前端项目 |
| 部署 | 先在 Windows 本机运行，目录与缓存放 E 盘 | 独立环境；软件、依赖或模型安装前检查磁盘及目标位置；全天在线主机后续再决定 |

这些版本已在本机共同加载成功，固定源码提交见 upstream.lock.json。加载成功与数据层测试不能证明完整 QQ 消息链路兼容；真实账号联调仍待完成。插件升级前备份数据。

## 复用原则

1. 先查框架已有配置，再查现有插件，最后才考虑小型扩展。
2. 人格、会话、发送、模型调用和定时器均只保留一套主负责组件。
3. 保留上游结构，必要扩展通过插件公开接口完成，避免长期维护自改框架分支。
4. 不引入 LangChain、Dify、独立 FastAPI 服务、Redis、PostgreSQL 或独立向量数据库来重复现有能力。AstrBot 本身带来的内部依赖仍按上游保留。
5. 第一阶段以一对一文本、记忆与少量主动消息为范围；语音输入、专属音色、空间动态和手机操作另按实际需求选择已有扩展。

## 唯一待解决的选型兼容问题

陪伴插件明确列出 qq_official，但配套记忆插件只列 aiocqhttp。因此此前方案中的“QQ 官方机器人 + 两个插件”应理解为待验证组合，不能描述成已确认即插即用。

先核对记忆插件现有的身份映射、会话钩子和平台依赖，再做目标账号验证。不能只添加一行 support_platforms 就宣称兼容。若实际不支持，优先更换现成记忆插件。NapCat 仅在用户确实需要普通 QQ 好友身份、且现行授权与账号条件适合时评估，不因一个插件不兼容就默认切换通道。

## 实施顺序

1. 使用 AstrBot 基线和 QQ 官方适配器，验证单聊收发、DeepSeek 回复与重启恢复。
2. 配置一个角色，启用陪伴插件，验证只回复一次、正确称呼、主动消息和免打扰。
3. 验证长期记忆插件，核对重启后记忆保留、来源准确及不同用户隔离。
4. 启用 Edge TTS，验证手机收到可播放的原生语音条；合成音频文件成功不等于投递成功。
