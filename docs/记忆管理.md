# 查看、纠正与删除记忆

本阶段复用 memory_companion 的原有管理面板、记忆引擎和数据库，没有另做记忆系统。

## 怎么使用

1. 登录本机面板 http://127.0.0.1:6185，进入左侧“我会牢牢记住你”。
2. 在顶部搜索框输入关键词或记忆 ID，按回车；也可进入“记忆检视”筛选。
3. 点击一条记忆，核对内容、来源会话及人格，确认属于要管理的机器人。
4. 在详情下方修改“内容”，点击“保存修改”。只纠正文字时，保留原来的可见性与生命周期。
5. 删除时点击详情中的“删除”，再在确认框中确认。删除不可撤销，重要内容先备份。

本机面板是管理员入口，可以看见不同机器人、不同会话的记录。QQ 中的记忆工具按会话身份隔离，这与管理员能查看全部记录是两个权限范围。当前已经验证两个不同 QQ 机器人；同一个机器人任意切换人格的隔离体验尚未完整验收。

## 纠正和删除的范围

修改的是这条长期记忆的当前内容；原始证据和历史聊天会保留。真实验收中，机器人正确回答了修改后的值，同时提及原始证据里的旧值。因此不能将“纠正”理解为清除全部历史痕迹。

删除会移除选中的长期记忆记录，不会自动删除原始聊天、历史会话、其他记忆或备份。如果旧信息仍在当前上下文或其他记录中，机器人仍可能知道它；后续摘要也可能再次提炼。希望核对长期记忆时，可以发送 `/new` 建立新会话，再询问相关内容；此命令保留旧会话。

## 本次修复的上游问题

固定版本 v2.3.1 的传统面板使用了旧的选项值。原记录为 `private_pair / stable_memory` 时，详情选项没有匹配项，浏览器会默认选择 `public / active`。即使只改文字，保存也会误写权限与状态。检索诊断明确返回 `unknown_visibility:public`，QQ 因而检索不到该记录。

本地兼容修复只调整已安装面板的选项和筛选项，使其使用引擎的实际值；遇到未知值也保留原值，不悄悄替换。未改变权限判断、隔离策略、数据库或服务端接口。原始 vendor 检出保持不变，修复脚本、备份与验证可独立检查。

维护命令（在项目目录使用已有 Conda 环境）：

```powershell
& ./runtime/conda/python.exe scripts/repair_memory_panel.py --check
& ./runtime/conda/python.exe scripts/repair_memory_panel.py
```

脚本仅接受已核对的原始文件摘要或已修复文件，拒绝覆盖其他修改；重复执行不重复打补丁。原文件保存在 `runtime/backups/memory-panel/`。升级插件可能覆盖修复，新版本需要重新核对，不能盲目套用。修复后刷新面板再编辑；本轮验收范围是当前传统面板，新版界面尚未单独验收。

## 验证

- 在真实 QQ 创建唯一临时测试记忆，从真实 Edge 面板搜索、打开详情、纠正并保存；接口确认内容更新且权限、状态保持。
- 大肥鱼建立新会话后，通过记忆工具取得修改后的当前值；GPT大人的新会话没有查到这条记忆。
- 使用原有面板的确认框删除该测试记录，详情接口返回 404；大肥鱼再次建立新会话后，记忆工具与手机回复均确认没有匹配记录。
- 真实上游数据层测试覆盖纠正、删除、重新打开服务后的结果，以及不同用户、群聊、机器人和两个人格绑定的隔离。本轮没有重启生产服务，修改与删除持久化由临时数据目录的真实数据层复开测试验证。
- 浏览器回归在修复前有 3 项失败，修复后通过；另验证补丁重复执行和拒绝覆盖其他修改。项目共 14 项测试通过。

脱敏结果见 `verification/memory-management-checks.json`。完整消息、截图、测试记录 ID、数据备份和浏览器登录状态仅存放在本机私有目录，不进入源码包。
