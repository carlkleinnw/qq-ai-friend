# 多机器人与人设同步（0.5.0）

## 机器人进入面板

在“好友人设”点击“接入与管理 QQ 机器人”，通过 AstrBot 原生 QQ 官方扫码流程选择已有机器人，或创建一个新机器人，取得凭据后保存。保存后的机器人自动进入人设页；停用的机器人仍可编辑已保存的人设，删除接入后从列表移除，原人格与聊天记录保留。名称来自 QQ 官方连接返回的机器人资料；连接未就绪时显示本机名称或实例标识。

在 QQ 官方平台创建账号，不等于本机已取得连接权限。每个新账号需完成一次官方绑定并保存。本项目不读取 QQ 密码，也不根据通讯录昵称猜测 AppID。多个本地实例绑定同一个 AppID 仍是同一个 QQ 账号。

新增接入通过 AstrBot 的平台加载事件自动建立独立人格和配置文件，路由使用 `[机器人实例ID]::`，已有的具体会话规则保留在默认规则之前。已存在的路由、模型、人格与数据不被初始化覆盖。发现已有人格被多个机器人共用时，保留原来的编辑保护，请在原生配置中独立绑定后再编辑。非原生 Agent 的人设继续使用其自身配置。

## QQ 与网页管理同一份人设库

| 操作 | QQ 私聊指令 |
| --- | --- |
| 列表 | `/人设` |
| 创建并填写 | `/新建人设 贴心搭子 | 温柔细心，说话简短。` |
| 分两条创建 | 先发 `/新建人设 贴心搭子`，再发人设内容 |
| 查看 | `/查看人设 贴心搭子` |
| 编辑内容 | `/编辑人设 贴心搭子 | 新的人设内容` |
| 修改名字 | `/重命名人设 贴心搭子 | 新名字` |
| 删除 | `/删除人设 贴心搭子` |
| 确认或取消 | `/确认人设`、`/取消人设` |
| 应用到当前机器人 | `/人设 贴心搭子`，预览后 `/确认人设` |
| 查看当前生效默认值 | `/当前人设` |

名称可以替换成列表中的编号或完整稳定标识。英文别名为 `presets`、`newpersona`、`showpersona`、`editpersona`、`renamepersona`、`deletepersona`、`confirmpersona`、`cancelpersona` 和 `currentpersona`，与中文使用同一个处理器。

所有修改先预览，十分钟内确认。在电脑“好友人设”页面选择机器人，打开“允许 QQ 编辑人设”开关后即可使用，无需发送 /sid 或复制会话标识。开关对每个机器人单独保存，默认关闭；开启后，任何与该机器人私聊的人都能创建、编辑、删除和应用人设，不授予系统管理员能力，群聊仍不可修改。关闭后管理员也不可在 QQ 编辑，并取消该机器人的待确认草稿；网页仍可管理。旧私聊授权名单不再决定编辑权限。编辑、改名、删除会校验预览时的版本，别人已修改时拒绝覆盖。

网页已有“新建自定义预设”“编辑选中预设”“删除选中预设”和搜索。两端共用 AstrBot 原生 PersonaManager 与 SQLite 数据库，没有新增人设数据库。编辑删除会同步人设列表及 QQ 选择菜单，稳定标识不会随改名改变。删除仅从库中隐藏，保留已应用的人设和历史。

**保存到库与应用是两个操作。** 新建、编辑或删除预设不会自动替换正在聊天的人设。QQ 选择预设并确认，或网页载入后保存，才会修改所选机器人的默认人设。旧 `/自定义人设 内容` 仍可用于仅修改当前机器人。公开 QQ 资料卡简介不属于聊天人设接口，仍使用手动复制粘贴。

## 同步与并发

网页在打开时每五秒检查机器人、库与当前人设。没有草稿时自动显示其他端保存的内容；有未保存草稿时显示提示并保留草稿，需复制后重新读取核对。弹窗填写期间暂停刷新。电脑离线、程序停止或页面隐藏时不承诺即时同步；重新打开后读取最新值。

QQ 菜单复用官方 `/v2/menu`，每组最多五个人设；保留无关菜单。菜单失败不撤销已保存的人设，页面提示并允许重试。后台每三十秒为已连接的机器人核对变更。QQ 客户端菜单可能需要关闭再打开私聊才刷新。

陪伴关系、记忆和音色仍由已有插件与配置管理；本次不复制其他机器人的私人资料。已启用的陪伴插件多人格模式会自动登记新机器人的人格，并调用插件自身的独立配置创建操作，复制技术参数而不复制私人资料，避免回退到主人格。其接口适配针对安装包锁定的上游版本；若同步失败会提示，并暂停该机器人的普通聊天，直到配置恢复。安装维护页“同步 QQ 机器人”仍可手动重试。人设保存不会替你启用模型、工具或外部服务。

## 实现依据与恢复

复用 [AstrBot 人格管理接口](https://docs.astrbot.app/dev/star/guides/ai.html)、[QQ 官方接入流程](https://docs.astrbot.app/platform/qqofficial/websockets.html) 及已锁定 AstrBot 4.29.1 的原生配置管理器、平台事件和 QQ SDK。升级通过现有安装器生成程序回退点和原生数据备份；私人备份仅放在本机 runtime，不进入代码仓库或安装包。

原生插件上下文未直接暴露配置新增后的消息流程加载方法。安装器沿用项目已有的固定版本修复方式，仅向插件上下文提供原生 `reload_pipeline_scheduler` 回调；新路由在该原生操作成功后才发布。修复核对上游文件完整哈希，遇到其他改动会停止覆盖，不实现另一套消息处理器。
