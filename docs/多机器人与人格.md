# 多机器人与人格

## 当前组合

| QQ 名称 | 人格页面中的 ID | 配置文件 | 陪伴资料 |
| --- | --- | --- | --- |
| 大肥鱼 | qq-friend | 大肥鱼独立配置 | 继续使用原来的主资料 |
| GPT大人 | gpt-lord | GPT大人独立配置 | 已创建独立资料与状态库 |

两个是真正不同的 QQ 机器人 AppID，各自有启用的 WebSocket 连接。“GPT大人”沿用已配置的 DeepSeek，名称不代表切换了模型供应商。

现有“大肥鱼”曾出现两条指向同一 AppID 的连接，重复条目已停用并保留，避免两个连接同时接收同一账号消息。这种重复条目不能算第二个机器人。

## 用户如何设计各自的人设

进入 AstrBot 的“人格”页面，分别编辑 qq-friend 和 gpt-lord，性格、语言、背景均由用户决定。大肥鱼的原有人设未改写；GPT大人只有可编辑的基础身份与工具结果约束。

每个机器人使用自己的配置文件，配置中“Agent 执行器 → 人格”选择对应人格。模型也可以在各自配置中单独选择；当前两者共用同一个已配置模型提供商与密钥，不会为每个人格复制一份 API Key。

陪伴插件已开启原有“多人格模式”，列表包括这两个人格；主人格 qq-friend 负责保留旧资料及回退，不覆盖框架已经解析出的其他有效人格。gpt-lord 的陪伴配置通过插件原有“创建人格配置”接口创建，复制技术参数，不复制主资料中的用户、关系、日记和聊天记忆。

## 增加第三个机器人

1. 在“机器人”页面扫码创建不同的 QQ 机器人，确认凭据自动填入后保存。核对 AppID 不同，避免重复绑定同一个账号。
2. 在“人格”页面创建并编辑它自己的角色，按需选择原有记忆、提醒等工具。
3. 新建独立配置，选择该人格与模型，并使用 AstrBot 原有配置路由，将该机器人实例下的会话指向该配置。
4. 在陪伴插件的多人格列表加入人格，并在陪伴面板为其创建独立配置；不要只填写人格 ID 就认定资料库已经建立。
5. 用手机分别验证身份、上下文和记忆，确认没有相互串用。

机器人级路由复用 AstrBot 的 `[机器人实例ID]::` 匹配格式，对该机器人下的会话生效。框架按首次匹配选择配置；机器人规则应放在广泛匹配规则之前。会话中已有的强制模型/人格规则可能覆盖配置默认值，需在原有会话设置中核对。

参考：[AstrBot 配置文件](https://docs.astrbot.app/dev/astrbot-config.html)、[自定义规则与覆盖关系](https://docs.astrbot.app/use/custom-rules.html)。本机使用 4.29.1，字段与操作以该版本实际界面和源码为准。

## 数据与限制

- 本轮重点验证两个不同 QQ 账号的配置、会话和记忆；不是同一个 QQ 机器人下任意切换人格的全面隔离承诺。
- 用户私聊记忆由记忆插件按会话与机器人归属判断可见性；陪伴关系和状态使用插件原有多人格存储。没有新增自研记忆系统。
- 验证时用 `/new` 新建会话，旧聊天历史保留；重启后召回要通过现有记忆注入或工具，避免误把仍在上下文中的内容当作长期记忆。
- 修改前的本机私有备份在 runtime/backups/before-multibot-data；其中含私人数据，不能公开上传。
- scripts/setup_multibot.py 仅调用原有 API 配置当前两个机器人，重复运行会保留已有人设与独立配置。不要把初始化预设重新覆盖到已使用环境。
