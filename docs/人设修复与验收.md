# 人设管理、QQ 同步与工具修复（0.4.3）

日期：2026-10-22。针对当前 Windows 安装目录修复，沿用 AstrBot 4.29.1，没有更换聊天引擎、数据库或 QQ 接入方式。

## 检查结果

- 0.4.2 的窗口只有新增预设接口，没有预设修改和删除接口。源码和已安装插件一致，缺口发生在功能实现。
- 原生数据库及插件索引中已有用户创建的自定义预设，不能把“未应用到机器人”一概视为“数据库没有保存”。此前的表单保存到预设后不会切换当前人格，提示和入口不足。
- 窗口预设列表只收录内置项和插件索引，漏掉原生人格页面中创建的人格。
- 创建预设时显式写入 tools=[]、skills=[]，使新原生人格不具备工具。原来的当前人设保存路径会保留工具，但窗口没有选择、诊断入口。
- DeepSeek 聊天提供商处于停用状态；日志出现“未找到任何对话模型”。本轮验证现有凭据可用后，通过原生接口启用原有模型，并通过连接测试。
- QQ 私聊编辑授权列表为空。根据用户主动提供的 /sid 信息，仅授权该私聊的人设编辑功能，没有添加系统管理员。
- 原菜单使用可变列表序号选择内置预设，增删后可能选错；删除分组后旧菜单页也不会清除。

## 复用来源与选型

1. [AstrBot 官方 PersonaManager 文档](https://docs.astrbot.app/dev/star/guides/ai.html)：继续用原生 create/get/update 接口写数据库及刷新人格缓存，复用现有路由和权限；没有另建人设数据库。
2. [AstrBot 原生实现](https://github.com/AstrBotDevs/AstrBot/blob/master/astrbot/core/persona_mgr.py)：核对本机固定版本，严格保留 tools 的三种语义：null 为全部工具，[] 为不使用工具，列表为指定工具。省略 skills 等字段以保留原值。
3. [AstrBot MCP 官方指南](https://docs.astrbot.app/use/mcp.html)：通过原生插件/MCP 管理接入服务，再在人格中选工具；不自行实现 MCP 客户端或另造工具协议。
4. [SillyTavern 角色管理指南](https://docs.sillytavern.app/usage/characters/)：参考已有的列表、搜索、创建、编辑、删除交互；没有引入第二个聊天服务，也没有复制其源码。
5. QQ 菜单继续使用当前 QQ 官方适配器已经认证的 botpy HTTP 客户端。实际 GET/PUT /v2/menu 返回版本号已核对；资料卡简介仍按平台现有入口手动设置，不将菜单同步宣传为 QQ 资料同步。

## 使用方式

1. 打开“好友人设”，选择机器人。
2. 新建：填写名称和内容，预览，再“保存到预设”。这一步保存到列表和同步 QQ 菜单。
3. 应用：选择预设，点击“载入预设”，再“保存人设”。只载入草稿时不会改机器人人设。
4. 修改预设：选择条目，点击“编辑选中预设”，预览并保存。内容和名称可修改，选择标识保留。
5. 删除预设：点击“删除选中预设”并确认。从本机列表及 QQ 菜单移除，原生内容保留，已应用的人设和聊天不被删除。内置预设也可编辑或移除；删除采用可恢复方式。
6. 搜索：可按名称、简介或正文搜索；点击“刷新列表”读取其他页面的更改。原生人格库条目带“原生”标记，避免同名混淆。
7. 工具：选择“仅使用勾选的工具”“使用全部已启用工具”或“不使用工具”，再“保存人设”。列表包含原生内置工具、插件和已接入 MCP 工具；未加载/停用的条目明确标记。保留已有工具顺序与未加载工具引用。
8. QQ：点击“同步 QQ 人设菜单”。首次私聊编辑时，发送 /sid，把完整 UMO 粘贴到窗口并授权。在 QQ 选择预设后发送 /确认人设 保存，或 /取消人设 放弃。

新预设继承所选机器人的工具和 Skills。载入预设时沿用当前机器人的工具选择；需要改变权限时在工具区明确勾选。工具是否实际可用还取决于模型支持、插件启用、服务连接及各工具自身权限。

QQ 菜单按稳定标识选择人设；原生长名称只在 QQ 菜单显示时截短，同名项添加数字区分，保存名称和选择标识不变。菜单更新保留无关菜单与元数据，清理本插件多余页，重复同步不重复增加条目。
