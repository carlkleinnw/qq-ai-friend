# 人设与聊天配置

## 用户自己设计人设

直接使用 AstrBot 原有“人格”页面，编辑当前的 qq-friend，保存后用于后续对话。名称、背景、说话方式和回复长短都由用户决定；QQ 资料卡里的昵称、头像仍在 QQ 中修改。

qq-friend 是初始样例，不是必须遵守的产品人设。本轮优化没有改写任何现有人设的文字、语言或工具选择。

也可以在 AstrBot 原有页面新建人格，再在配置中选择默认人格，或使用框架的会话人格选择功能。陪伴插件的“插件主人格 ID”留空，沿用上游支持的“跟随 AstrBot 当前/默认人格”方式，不再另行固定为 qq-friend。当前为单人格模式，陪伴关系和状态仍共用，不能将切换人设理解为完全隔离的多个 AI 好友。

如果新建人格需要长期记忆和提醒，请在该人格原有工具选择中启用 memory_companion_recall、memory_companion_query、memory_companion_remember，以及 future_task。已有 qq-friend 已配置这些工具。人格工具权限沿用上游，不自动对新建人格开放所有工具。

## 本轮技术调整

- 关闭陪伴插件的“被动回复前注入拟人状态”。此前仅关闭身体状态，总注入开关仍开着，普通聊天仍会获得额外生活背景。
- 关闭模拟休息回复与繁忙回复闸门，避免因为角色模拟日程导致普通消息无回应或被延迟。
- 人设路由复用 AstrBot；不另写人设管理、提示词拼接或语言润色服务。
- 现有的人设、聊天历史、用户记忆和密钥保留。历史中的旧回复仍可能影响后续上下文；修改人设后若要干净地体验新角色，可用框架原有的新会话/重置上下文功能，不必删除长期记忆。

这些设置减少技术注入与用户人设的冲突，不保证模型永远不会编造，也不禁止用户主动设计虚构角色。角色表达由用户的人设决定；真实操作和提醒是否成功仍应以工具结果为准。

## 维护入口

更新预设见 config/mvp-overrides.json。scripts/optimize_chat.py 通过原有管理 API 应用本轮少量配置，并核对人设完全未变；它不会重新运行初始化或重装插件。修改前的插件配置仅备份到 verification/private，不进入源码包。
