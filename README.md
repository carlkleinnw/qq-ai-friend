# QQ AI 好友 MVP 0.1.0

基于 AstrBot 4.29.1、QQ 官方机器人、DeepSeek 官方 API，以及现有陪伴和记忆插件。业务主体沿用上游，项目只提供本机启动入口、初始配置和交付检查。

## 打开与停止

1. 双击 `启动AI好友.cmd`，浏览器打开本地管理面板。
2. 登录信息查看 `查看登录说明.cmd`。此文件打开的本机说明仅存放在 runtime，不进入源码包。
3. 面板地址：<http://127.0.0.1:6185>。若浏览器没有自动打开，手动访问该地址。
4. 需要关闭时双击 `停止AI好友.cmd`，不要直接结束其他 Python 或 Conda 进程。

程序使用 `E:\chatbot\runtime\conda` 的独立 Conda 环境，运行数据在 `runtime\app\data`。启动时无需手动激活环境。

## 填写自己的 DeepSeek API Key

1. 进入左侧“模型提供商”，点击 `deepseek`。
2. 在 API Key 密码输入框中填写自己的密钥，点击“保存配置”。
3. 在下方已配置的模型中启用 `deepseek/deepseek-flash`。其默认状态是关闭，避免未填密钥就反复请求。
4. 可点击“获取模型列表”检查鉴权和网络；这不等于对话已实测成功。
5. 点击顶部“聊天”，选择该模型，发送一句话，检查真实回复。

模型地址已预填官方地址 `https://api.deepseek.com/v1`。密钥不需要发给开发者，也不应粘贴到人设或聊天里。

密钥按 AstrBot 原有方式保存在本机 runtime 配置中；运行目录包含私人数据，不能作为公共源码包上传。输入框遮罩不代表磁盘文件已加密。

## 接入 QQ

1. 进入左侧“机器人”→“创建机器人”。
2. 选择“QQ 官方机器人（WebSocket）”→“扫码一键创建”。
3. 按页面指引，用自己的手机 QQ 扫码确认。等待 AppID 和 AppSecret 自动填入后，确认启用并点击“保存”。仅在手机创建机器人，还没有完成与本机的连接；如果提示未连接“灵魂”，先核对面板是否已保存机器人、状态是否在线。
4. 在 QQ 开放平台的机器人入口选择“扫码聊天”，从手机进入单聊。
5. 先发一句“你好”，核对本机日志收到消息，手机收到真实 AI 回复。

QQ 显示名称、头像由你在 QQ 创建流程中设置。程序的人设配置名 `qq-friend` 只是内部标识，不会替你固定 QQ 昵称。陪伴面板的“Bot 名字”也可按你取好的名字同步修改。

QQ 登录、账号权限和消息投递需要真实账号完成。面板显示已配置或某个接口返回成功，不等于手机实际收到消息。

## 多机器人与不同人格

现已接入两个不同的 QQ 机器人：“大肥鱼”对应 qq-friend，“GPT大人”对应 gpt-lord。每个机器人有独立配置和陪伴资料；人设文字直接在原有“人格”页面分别编辑。两者目前均使用已配置的 DeepSeek。

已用真实手机验证两边收发，以及服务重启、新建会话后的各自记忆召回。配置方法、第三个机器人的添加步骤和验证边界见 [多机器人与人格](docs/多机器人与人格.md)。

## 第一版已配置的体验

- 提供初始人设样例；角色、语言和表达方式由用户在原有“人格”页面自行设计，操作见 [人设与聊天配置](docs/人设与聊天配置.md)。
- AstrBot 的持久化会话与本地数据库，程序关闭后已保存的记录保留。
- 原有长期记忆插件及记忆工具，私聊记忆按身份隔离。
- 复用原有记忆面板查看、纠正与删除记录；已修复传统面板保存时误写权限的问题，操作和删除范围见 [记忆管理](docs/记忆管理.md)。
- 原有陪伴面板与未来任务；用户明确要求时可创建定时提醒。
- Edge TTS 提供商与 FFmpeg，已生成过真实语音样例。默认仍发送文字；需要自动语音时，在配置文件的文字转语音设置选择 `edge_tts` 并启用。

主动联系默认不对所有新联系人开放。首次 QQ 私聊后，可在“陪伴面板”的对应用户档案里开启主动权限并设置额度、免打扰；也可以在聊天中明确提出定时提醒，并到“未来任务”核对保存的目标会话和时间。

定时提醒直接使用 AstrBot 原有功能，支持一次性、重复、查看与取消；操作和运行限制见 [定时提醒](docs/定时提醒.md)。这类用户明确建立的任务不需要为所有联系人开启主动陪伴。

第一版关闭群聊学习、设备访问、空间动态、生图、模拟身体状态等扩展，集中验证单人聊天、记忆和提醒。图片识别与双向语音后续根据实际需求开启现有组件。

## 验证状态

检查结果以 `verification/runtime-checks.json` 与 `docs/MVP交付验收.md` 为准。区分：

- 本地面板、登录、插件加载和配置检查；
- 不连接 QQ / 模型的记忆与平台逻辑测试；
- 用户自己的密钥和 QQ 账号上的真实对话、消息投递。

其中前两类不能替代第三类。已完成 DeepSeek 真实网页对话、两个手机 QQ 机器人单聊收发及重启后的记忆召回；2026-10-21 又验证了聊天创建/取消提醒、重启保留与两个机器人实际定时投递，以及面板纠正记忆后的真实 QQ 召回、跨机器人隔离和面板删除后新会话检索为空。当前项目 14 项测试通过，语音投递仍待验证。上游部分回归测试存在未通过项，具体原因和数量见验收记录。

## 复用与维护

- 框架和插件来源、固定提交见 `upstream.lock.json` 与 `THIRD_PARTY.md`。
- Python 依赖见 `requirements.lock.txt`，Conda 环境定义见 `environment.yml`。
- 配置初始化脚本不会覆盖已经存在的用户配置。不要删除 runtime 来解决普通连接问题。
- 更换机器前备份整个 `runtime\app\data`；需要随数据迁移模型密钥时，使用你自己控制的安全存储。
- 升级插件前备份配置和数据，先阅读对应版本迁移说明。

开发者重建时，在 E 盘创建 Python 3.12 Conda 环境，按锁定依赖安装，并将锁定版本的两个插件检出到 `runtime/vendor`；运行 `scripts/init_mvp.py`、启动程序，再运行 `scripts/apply_profile.py`。不在当前已配置的用户环境里反复执行初始化或重装。

安装固定版本记忆插件后，运行 `scripts/repair_memory_panel.py` 应用已验收的传统面板兼容修复，再刷新页面。该脚本不修改记忆数据，版本或文件内容不匹配时会拒绝覆盖，详见记忆管理说明。
